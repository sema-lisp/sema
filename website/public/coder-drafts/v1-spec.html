A coding agent you can read in an afternoon.

Sema Coder edits files, runs commands, and searches code from the terminal. All of it — the agent loop, the tools, the TUI, the MCP client, the config language — is Sema source in one repository. There is no build step.

How it works

Three modes, one binary.

Run it on a terminal and you get the full-screen interface. Pipe into it and you get plain output you can put in a script.

  • Interactive. ./coder.sema opens the full-screen TUI: streamed turns, scrollback, selection, modal overlays.
  • One-shot. -p "…" prints the answer and exits. --json prints exactly one JSON document instead.
  • Piped. Anything on stdin is appended to the prompt inside a <stdin> block.
  • Not a TTY. Without --print, it falls back to a plain line-based REPL.
# ask about the repo you are in
$ ./coder.sema -- -p "explain this codebase"

# one JSON document on stdout
$ ./coder.sema -- --json -p "..."

# pipe context in
$ git diff | ./coder.sema -- \
    -p "review this change"

# pick a model for this run
$ ./coder.sema -- -m claude-haiku-4-5

Tools

Ten, with limits.

Each tool caps its own output, so a large file or a noisy command cannot fill the context window.

read-file
Line-numbered read. Refuses binaries and files over 2 MB; caps at 2,000 lines.
write-file
Create or overwrite, creating parent directories. Reports the old size when it overwrites.
edit-file
Replace one exact string; the result includes a diff. Needs a unique match unless replace_all.
bash
Shell command in the workspace. 120-second default timeout, or background=true for a task id.
task-output / task-list / task-stop
Read, list, and terminate background tasks. Stopping kills the process group.
grep
Prefers rg, falls back to grep. Argv-style, so a pattern cannot smuggle shell syntax.
find-files
Glob search, skipping .git, node_modules, and target.
list-dir
One directory, long format.

Every file and search path is checked with path/within?, which resolves symlinks, so ../ and symlink escapes both fail. The bash tool is not covered: it runs real commands with your privileges. This is accident prevention, not a sandbox.

Configuration

The config file is a program.

init.sema calls (configure! (coder-config {…})). Because it is code, a slash command can be a lambda and a hook can close over state. Loading is pure: a broken file keeps the last good commands, servers, hooks, and tools instead of wiping them.

  • Written on first run at <config-dir>/sema/sema-coder/init.sema.
  • Hot reload. The TUI watches the config directory; /reload does it by hand.
  • Unknown keys warn rather than fail, so a typo cannot lock you out.
(configure!
  (coder-config
    {:model     "claude-opus-5"
     :max-turns 50

     ;; MCP servers — stdio or http
     :mcp-servers
     (list
       (mcp-server "sema"
         {:command "sema"
          :args ["mcp"]
          :autostart #t}))

     ;; a slash command, as a lambda
     :commands
     (list
       (command "hi"
         {:desc "greet"
          :do (lambda (state args)
                (emit :info "hi!")
                state)}))}))

What you need.

ANTHROPIC_API_KEY or OPENAI_API_KEY. The model is auto-detected from whichever is set.

Disk
The repository. There is nothing to compile and no lockfile to resolve.

Questions

FAQ

Is any of it actually Rust?

Not in this repository — there is no .rs file and no Cargo.toml. What Rust there is lives in the sema binary, as the primitives Sema Coder calls: agent/run, async/*, term/*, proc/*, file/*, mcp/connect, path/within?.

Can it use my MCP servers?

Yes, over stdio or HTTP. Servers are declared in the config; :autostart #t connects at boot, and the rest connect from the /mcp modal (⌃O). Built-in tools win a name collision, and /tools shows which server each tool came from.

What happens if I press Ctrl-C during a tool call?

The turn is cancelled and the history is repaired: every orphaned tool call gets a synthesized, correlated result, the assistant text written so far is kept, and a control message records the interruption. The next turn starts from a history the provider will accept.

Does it remember sessions?

The TUI writes every turn to a JSONL file — one meta line, then one message per line in the shape agent/run takes — and /resume restores one verbatim. One-shot and the plain REPL do not persist.

How is it tested?

36 test files, 3,400 lines, run by a test runner that is itself Sema. Each file runs in a child interpreter, so a crash stays in that file. CI runs the version floor and the latest release.

Is it finished?

No. Agent-authored persistent tools and first-class workflows are designed but not built, and the context gauge is still missing from the header. The parts described on this page are the parts that exist.
