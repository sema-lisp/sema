(sema) coder A terminal coding agent · v0.3.0

We wrote the agent in the language.

Sema Coder edits files, runs commands, and searches code from the terminal. It is the answer to a fair question about a Lisp with LLM primitives: what does it look like when you actually build the thing?

sema-lisp/sema-coder · MIT · requires sema ≥ 1.35

The repository has no Rust in it

A coding agent is a real program. It needs a terminal interface that redraws without flicker, a loop that survives a cancelled tool call, a process supervisor for background commands, a client for someone else's protocol, and a configuration format people can live with.

Every one of those is a Sema file here. The agent loop, the ten tools, the full-screen interface, the modal overlays, the MCP client, the session store, the plugin system, the tests: .sema, all of it. There is no Cargo.toml in the repository and nothing to compile before you run it.

What is Rust lives one level down, in the sema binary, as the primitives the program calls — agent/run, async/*, term/*, proc/*, file/*, mcp/connect, path/within?. That is the whole boundary.

Running it

On a terminal you get the full-screen interface: streamed turns, scrollback, selection, modal overlays. Pipe into it and you get plain output fit for a script. Anything on stdin is appended to the prompt inside a <stdin> block. 

# ask about the repository you are in
$ ./coder.sema -- -p "explain this codebase"

# exactly one JSON document on stdout
$ ./coder.sema -- --json -p "..."

# pipe context in
$ git diff | ./coder.sema -- -p "review this change"

The interpreter's arguments come first and Sema Coder's come after --. It is a wart, and the repository says so.

Tools read-file, write-file, edit-file, bash, task-output, task-list, task-stop, grep, find-files, list-dir. Each caps its own output so one command cannot fill the context window.
Path safety Every file and search path goes through path/within?, which resolves symlinks. The bash tool is not covered — it runs real commands with your privileges. Accident prevention, not a sandbox.

The config file is a program

init.sema calls (configure! (coder-config {…})). Because the configuration is code, a slash command can be a lambda and a hook can close over state — no template syntax had to be invented for either. 

(configure!
  (coder-config
    {:model     "claude-opus-5"
     :max-turns 50

     :mcp-servers
     (list
       (mcp-server "sema"
         {:command "sema" :args ["mcp"] :autostart #t}))

     :commands
     (list
       (command "hi"
         {:desc "greet"
          :do (lambda (state args)
                (emit :info "hi!") state)}))}))

Loading is pure. A file that does not parse reconciles nothing and leaves the last good commands, servers, hooks, and tools running. An unknown key is a warning, so a typo cannot lock you out of your own agent.

Where <config-dir>/sema/sema-coder/init.sema, written on first run from the provider table so its model list cannot drift from the code.
Reload The TUI watches the config directory and applies a valid save; /reload does the same by hand. Both take one code path.

Cancelling a turn

Pressing Ctrl-C in the middle of a tool call is how an agent ends up with a history its provider rejects: a tool call with no result. The turn runs as an async task with a second task drawing the interface, so the cancel lands immediately — and then the history is repaired.

Every orphaned tool call gets a synthesized, correlated result. The assistant text written so far is kept. A typed control message records that the user interrupted and that partial side effects are possible. The next turn starts from something the provider will accept.

Sessions The TUI writes every turn to JSONL — one meta line, then one message per line in the shape agent/run takes — to a temp file that is renamed, so a crash mid-write cannot truncate the old one. /resume restores one verbatim. One-shot and the plain REPL do not persist.

What it proved, and what it broke

Writing a real application in a young language finds the holes. Thirteen of them were filed against the Sema repository as issues #82–#94. Eight are fixed and used here through released APIs. Five are still open and worked around in the source, which is the honest version of the story.

The tests are Sema too: a runner that launches each test file in a child interpreter so a crash stays in that file, and a harness whose summary must appear for a run to count as green. The turn controller is tested against a scripted runner and a no-op renderer, so cancellation and event ordering need neither a network nor a terminal.

  • Not built yet: agent-authored persistent tools, and workflows as a first-class feature. Both are designed; neither exists.
  • Missing: the context gauge in the header.
  • Known wart: the -- separator, and no streaming in one-shot mode.
