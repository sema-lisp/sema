sema-coder

A coding agent, written in Sema.

It edits files, runs commands, and searches code from the terminal. The agent loop, the ten tools, the full-screen interface, the MCP client, and the config language are .sema files in one repository. Nothing is compiled, and the only thing to install is the sema binary.

$ git clone https://github.com/sema-lisp/sema-coder

Requires sema ≥ 1.35 and either ANTHROPIC_API_KEY or OPENAI_API_KEY.

Three ways to run it

On a terminal you get the interface above. Without one you get plain output you can pipe. Arguments for the interpreter come first; everything after -- belongs to Sema Coder. 

$ ./coder.sema

Full-screen interface when stdout is a terminal: streamed
turns, scrollback, selection, modal overlays. Without a TTY
and without --print it falls back to a line-based REPL.
$ ./coder.sema -- -p "explain this codebase"

Runs one prompt, prints prose to stdout, exits.
-m <model> overrides the model for this run.
$ ./coder.sema -- --json -p "..."

{"status": "completed",
 "model":  "claude-opus-5",
 "usage":  {…},
 "response": "…"}

Exactly one JSON document; requires --print. A failure
prints "status": "failed" and exits non-zero.
$ git diff | ./coder.sema -- -p "review this change"

stdin is appended to the prompt inside a <stdin> block.
An AGENTS.md or CLAUDE.md in the workspace is added to the
system prompt, capped at 32 KB each.

Ten tools

Enough to do real work, with a cap on every result so one large file or one noisy command cannot fill the context window.

read-fileLine-numbered read. Refuses binaries and files over 2 MB; caps at 2,000 lines.
write-fileCreate or overwrite, creating parent directories on the way.
edit-fileReplace one exact string. The result carries a diff, capped at 60 lines.
bash120-second default timeout, or background=true to get a task id back immediately.
task-output
task-list
task-stop		Read, list, and terminate background commands. Stopping kills the whole process group.
grepPrefers rg, falls back to grep. Invoked argv-style, so a pattern cannot smuggle shell syntax.
find-filesGlob search, skipping .git, node_modules, and target.
list-dirOne directory, long format.
! what the path check does and does not cover
Every file and search path goes through path/within?, which resolves symlinks, so both ../ and symlink escapes fail. The bash tool is not covered — it runs real commands with your privileges. This is accident prevention, not a sandbox.

The config file is a program

init.sema is written on first run and calls (configure! (coder-config {…})). Because it is code rather than data, a slash command can be a lambda and a hook can close over state.

init.sema<config-dir>/sema/sema-coder
(configure!
  (coder-config
    {:model     "claude-opus-5"
     :max-turns 50

     ;; MCP servers — stdio or http
     :mcp-servers
     (list
       (mcp-server "sema" {:command "sema" :args ["mcp"] :autostart #t}))

     ;; a slash command, as a lambda
     :commands
     (list
       (command "hi" {:desc "greet"
                    :do (lambda (state args) (emit :info "hi!") state)}))}))
  • Loading is pure. A file that does not parse reconciles nothing and leaves the last good commands, servers, hooks, and tools running.
  • An unknown key produces a warning instead of a failure, so a typo cannot lock you out of your own agent.
  • The interface watches the config directory and applies a valid save on the spot; /reload does the same by hand.
  • The first-run template is generated from the provider table, so the model list in your config cannot drift from the one in the code.

It is an MCP client

Servers are declared in the config and managed from a modal on ⌃O. The one configured by default is Sema's own, so the agent can evaluate Sema and read Sema docs while it edits Sema.

/mcp3 servers
● sema connected · 3 tools
▲ asana needs auth — press c to sign in
◌ filesystem idle — press c to connect
↑↓ move · c connect · d disconnect · ⏎ tools · e edit · esc close
  • stdio (:command and :args) or HTTP (:url), with OAuth prompted when you connect.
  • :autostart #t connects at boot, before the alt-screen opens, so a first sign-in is visible.
  • On a name collision the built-in tool wins; between servers the first to connect wins; /tools shows where each tool came from.

Extending it

Put a .sema file in plugins/, globally or in a project's .sema-coder/plugins/. It loads at boot with the full API available. A broken plugin prints an error and the agent still starts.

register-command!A slash command with a (state args) handler, plus register-completions! for its arguments.
deftool
register-tool!		A tool the model can call. Files in tools/ are reconciled on every config apply.
add-hook!session-start, pre-turn, pre-tool-call, post-turn, on-error, turn-queued, turn-interrupted.
bind-key!Rebind any action across four merge layers. Conflicts are reported at boot.
register-overlay!A modal with :render and :on-key, or reuse list-modal — what the MCP manager is built from.
prompt-insert!Read and rewrite what the user is typing, from inside a command.

Interrupting a turn keeps the history valid

Cancelling during a tool call is how an agent ends up with a conversation its provider rejects: a tool call with no result. This one repairs the history before the next turn starts.

  • The turn runs as an async task and a second task keeps drawing, so keys stay live and ⌃C lands immediately.
  • Every orphaned tool call gets a synthesized, correlated result, and the assistant text written so far is kept.
  • A typed control message records that you interrupted and that partial side effects are possible.
  • Tab queues a follow-up instead of interrupting; /queue lists, edits, drops, and resumes.
  • The interface appends each turn to a JSONL session — one meta line, then one message per line — through a temp file that is renamed, so a crash mid-write cannot truncate the old one. /resume restores one verbatim; one-shot and the plain REPL do not persist.
