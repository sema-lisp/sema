A coding agent, written in Sema.

It edits files, runs commands, and searches code from the terminal. What follows is the sort of session you would have with it — the questions answered by the agent's own source.

A terminal coding agent. The agent loop, the ten tools, the full-screen interface, the modal overlays, the MCP client, the session store, the plugin system and the config language are all .sema files in one repository. Nothing is compiled before you run it.

There is no .rs file and no Cargo.toml here. The Rust lives one level down in the sema binary, as the primitives I call: agent/run, async/*, term/*, proc/*, file/*, mcp/connect, path/within?. That is the whole boundary.

▌how do I run you?
✓ read-file src/cli.sema · 92 lines0ms
$ ./coder.sema                              # full-screen TUI on a terminal
$ ./coder.sema -- -p "explain this repo"    # prose to stdout, then exit
$ ./coder.sema -- --json -p "..."           # exactly one JSON document
$ ./coder.sema -- -m claude-haiku-4-5       # override the model
$ git diff | ./coder.sema -- -p "review"    # stdin → <stdin> block

On a terminal you get the full-screen interface: streamed turns, scrollback, selection, modal overlays. Without a TTY and without --print I fall back to a plain line-based REPL. The interpreter's arguments come first and mine come after --; that is a wart and the repository says so.

If the workspace has an AGENTS.md or CLAUDE.md, it goes into my system prompt, capped at 32 KB each, so project conventions apply without pasting them in.

▌what can you actually do to my files?
✓ grep register-builtin-tool! src/tools.sema12ms
read-fileLine-numbered read. Refuses binaries and files over 2 MB; caps at 2,000 lines.
write-fileCreate or overwrite, creating parent directories.
edit-fileReplace one exact string; the result carries a diff.
bash120-second default timeout, or background=true for a task id.
task-output · list · stopRead, list, terminate background commands. Stopping kills the process group.
grep · find-files · list-dirSearch. rg when it is there, grep when it is not; argv-style, never through a shell.

Every file and search path is checked with path/within?, which resolves symlinks, so ../ and symlink escapes both fail. The bash tool is not covered — it runs real commands with your privileges. This is accident prevention, not a sandbox.

▌how am I supposed to configure you?
✓ read-file ~/…/sema-coder/init.sema0ms
(configure!
  (coder-config
    {:model     "claude-opus-5"
     :max-turns 50

     ;; MCP servers — stdio or http
     :mcp-servers
     (list
       (mcp-server "sema" {:command "sema" :args ["mcp"] :autostart #t}))

     ;; a slash command, as a lambda
     :commands
     (list
       (command "hi" {:desc "greet"
                    :do (lambda (state args) (emit :info "hi!") state)}))}))

The config file is a program. Because it is code, a slash command can be a lambda and a hook can close over state — no template syntax had to be invented for either.

  • Loading is pure. A file that does not parse reconciles nothing and keeps the last good commands, servers, hooks, and tools.
  • An unknown key is a warning, not a failure, so a typo cannot lock you out of your own agent.
  • The TUI watches the config directory and applies a valid save; /reload does the same by hand.
  • Written on first run from the provider table, so the model list in your config cannot drift from the code.

● sema        connected · 3 tools

↑↓ move · c connect · d disconnect · ⏎ tools · e edit · esc close

Yes — stdio or HTTP, with OAuth prompted on connect. That panel is the /mcp modal, on ⌃O. :autostart #t connects at boot, before the alt-screen opens, so a first sign-in is visible.

The server configured by default is Sema's own, so I can evaluate Sema and read Sema docs while editing Sema. On a name collision the built-in tool wins, between servers the first to connect wins, and /tools shows where each tool came from.

▌what happens if I hit Ctrl-C while you're running a command?
✓ read-file src/turn.sema · 107 lines0ms

The turn runs as an async task and a second task keeps drawing the interface, so the cancel lands immediately. Then the history is repaired, which is the part that usually goes wrong: a tool call with no result is a conversation the provider will reject.

  • Every orphaned tool call gets a synthesized, correlated result.
  • The assistant text written so far is kept.
  • A typed control message records that you interrupted and that partial side effects are possible.
  • If you would rather not interrupt at all, Tab queues a follow-up mid-turn.

In the TUI every turn is appended to a JSONL session — one meta line, then one message per line — written to a temp file and renamed, so a crash mid-write cannot truncate the old one. /resume restores one verbatim. One-shot and the plain REPL do not persist.

▌what's missing?
✓ read-file docs/ROADMAP.md0ms
  • Agent-authored persistent tools. Designed, not built — the host primitive does not exist yet.
  • Workflows as a first-class feature. Design only; no /workflows overlay.
  • The context gauge in the header, and streaming in one-shot mode.
  • Five upstream issues. Writing me found thirteen gaps in the language, filed as #82–#94. Eight are fixed and used here through released APIs; five are still open and worked around in the source.

The tests are Sema too: 36 files, 3,400 lines, each run in a child interpreter so a crash stays in that file, with CI covering the version floor and the latest release.
