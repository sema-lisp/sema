01 What is Sema, what is Rust

A coding agent is a real program. It needs an interface that redraws without flicker, a loop that survives a cancelled tool call, a supervisor for background commands, a client for someone else's protocol, and a config format people can live with.

Each of those is a Sema file here. What Rust there is lives one level down in the sema binary, as the primitives the program calls — agent/run, async/*, term/*, proc/*, file/*, mcp/connect, path/within?. That is the whole boundary.

02 Running it

On a terminal you get the full-screen interface. Pipe into it and you get plain output fit for a script. Interpreter arguments come first; everything after -- is Sema Coder's. 

$ ./coder.sema                              # full-screen TUI
$ ./coder.sema -- -p "explain this codebase"  # prose, then exit
$ ./coder.sema -- --json -p "..."            # one JSON document
$ ./coder.sema -- -m claude-haiku-4-5        # override the model
$ git diff | ./coder.sema -- -p "review"     # stdin → <stdin> block

Without a TTY and without --print it falls back to a plain line-based REPL. An AGENTS.md or CLAUDE.md in the workspace is added to the system prompt, capped at 32 KB each.

04 Tools

read-file
Line-numbered read. Refuses binaries and files over 2 MB; caps at 2,000 lines.
write-file
Create or overwrite, creating parent directories.
edit-file
Replace one exact string; the result carries a diff.
bash
120-second default timeout, or background=true for a task id.
task-output/list/stop
Read, list, terminate background commands. Stopping kills the process group.
grep
Prefers rg, falls back to grep. Argv-style, never through a shell.
find-files
Glob search, skipping .git, node_modules, target.
list-dir
One directory, long format.

Each caps its own output so one file or one noisy command cannot fill the context window. Every file and search path goes through path/within?, which resolves symlinks, so ../ and symlink escapes both fail. The bash tool is not covered: it runs real commands with your privileges. This is accident prevention, not a sandbox.

05 Config as a program

(configure!
  (coder-config
    {:model     "claude-opus-5"
     :max-turns 50

     ;; MCP servers — stdio or http
     :mcp-servers
     (list
       (mcp-server "sema" {:command "sema" :args ["mcp"] :autostart #t}))

     ;; a slash command, as a lambda
     :commands
     (list
       (command "hi" {:desc "greet"
                    :do (lambda (state args) (emit :info "hi!") state)}))}))
  1. It is code. A slash command can be a lambda and a hook can close over state, so no template syntax had to be invented.
  2. Loading is pure. A file that does not parse reconciles nothing and keeps the last good commands, servers, hooks, and tools.
  3. Unknown keys warn. A typo cannot lock you out of your own agent.
  4. Hot reload. The TUI watches the config directory and applies a valid save; /reload does the same by hand.
  5. Generated on first run from the provider table, so the model list cannot drift from the code.

06 MCP client

/mcp  —  ^O

● sema        connected · 3 tools
▲ asana       needs auth — press c to sign in
◌ filesystem  idle — press c to connect

↑↓ move · c connect · d disconnect · ⏎ tools · e edit · esc close
  1. stdio or HTTP, with OAuth prompted on connect.
  2. :autostart #t connects at boot, before the alt-screen opens, so a first sign-in is visible.
  3. The default server is Sema's own, so the agent can evaluate Sema and read Sema docs while editing Sema.
  4. Collisions are reported. Built-ins win; between servers the first to connect wins; /tools shows each tool's origin.

07 Extending

A .sema file in plugins/, globally or per project, loaded at boot with the full API. A broken plugin prints an error and the agent still starts.

register-command!
A slash command with a (state args) handler; register-completions! for its arguments.
deftool, register-tool!
A tool the model can call. Files in tools/ are reconciled on every config apply.
add-hook!
session-start, pre-turn, pre-tool-call, post-turn, on-error, turn-queued, turn-interrupted.
bind-key!
Rebind any action over four merge layers; conflicts reported at boot.
register-overlay!
A modal with :render and :on-key, or reuse list-modal.
prompt-insert!
Read and rewrite what the user is typing, from inside a command.

08 Interrupting a turn

Cancelling during a tool call is how an agent ends up with a history the provider rejects. The turn runs as an async task with a second task drawing the interface, so the cancel lands immediately — then the history is repaired.

  1. Orphaned tool calls get synthesized, correlated results.
  2. In-flight assistant text is kept rather than dropped.
  3. A typed control message records the interruption and that partial side effects are possible.
  4. Tab queues a follow-up instead of interrupting; /queue lists, edits, drops, resumes.
  5. Sessions are JSONL, written by the TUI to a temp file and renamed. /resume restores one verbatim; one-shot and the plain REPL do not persist.

09 Tests, and what is missing

36 test files, 3,400 lines, run by a test runner that is itself Sema. Each file runs in a child interpreter so a crash stays in that file, and a passing child must print the harness summary, so a forgotten (done) cannot report a false pass. CI runs the version floor and the latest release.
