sema-coder

A coding agent, written in Sema.

It edits files, runs commands, and searches code from the terminal. The agent loop, the ten tools, the full-screen interface, the MCP client and the config language are .sema files in one repository. Nothing is compiled. The only thing to install is the sema binary.

~7,000 lines of Sema· 23 source files· 10 tools· no build step· MIT

Get started

Three commands. The first installs the interpreter, the second gets the agent, the third runs it.

1$curl -fsSL https://sema-lang.com/install.sh | sh
2$git clone https://github.com/sema-lisp/sema-coder && cd sema-coder
3$export ANTHROPIC_API_KEY=… && ./coder.sema

Needs sema 1.35 or newer, and one of ANTHROPIC_API_KEY or OPENAI_API_KEY. Homebrew (brew install helgesverre/tap/sema-lang) and cargo install sema-lang also work. Install rg and the grep tool uses it instead of grep.

Ways to run it

Arguments for the interpreter come first. Everything after -- belongs to Sema Coder.

shell
$ ./coder.sema                                   ; full-screen interface
$ ./coder.sema -- -p "explain this codebase"     ; one shot, prose, exit
$ ./coder.sema -- --json -p "..."                ; one JSON document
$ ./coder.sema -- -m claude-haiku-4-5            ; pick the model
$ git diff | ./coder.sema -- -p "review this"    ; stdin in a <stdin> block
terminalThe full-screen interface: streamed turns, scrollback, selection, modal overlays.
no TTYWithout --print it falls back to a line-based REPL.
--printRuns one prompt, prints prose to stdout, exits.
--jsonPrints one JSON object: status, model, effort, usage, elapsed_ms, and response or error. Requires --print. A failure exits non-zero.
stdinAppended to the prompt inside a <stdin> block when stdin is not a terminal.
AGENTS.mdAn AGENTS.md or CLAUDE.md in the workspace is added to the system prompt, 32 KB each at most.

Ten tools

Every result is capped, so one large file or one noisy command cannot fill the context window.

toolwhat it does
read-fileLine-numbered read. Refuses binaries and files over 2 MB. Caps at 2,000 lines.
write-fileCreate or overwrite. Creates parent directories. Reports the previous size.
edit-fileReplace one exact string. Needs a unique match unless replace_all. Returns a diff, 60 lines at most.
bashShell command in the workspace. 120-second default timeout. background=true returns a task id at once.
task-outputRead a background task's retained output and status.
task-listList background tasks in this process.
task-stopTerminate one. On Unix the whole process group is killed.
grepPrefers rg, falls back to grep. Run argv-style, so a pattern cannot reach a shell.
find-filesGlob search. Skips .git, node_modules and target.
list-dirOne directory, long format.

Every file and search path goes through path/within?, which resolves symlinks, so ../ and symlink escapes fail. The bash tool is not covered. It runs real commands with your privileges. This is accident prevention, not a sandbox.

MCP client

Sema Coder connects to MCP servers over stdio or HTTP and merges their tools into the agent. ⌃O opens the manager over the transcript. The server configured by default is Sema's own, so the agent can evaluate Sema and read Sema docs while it edits Sema.

Configuration

Config is Sema data, not JSON. init.sema calls (configure! (coder-config {…})) and is written on first run. Because it is code, a command can be a lambda and a hook can close over state.

Where files live

init.sema<config-dir>The config itself. Watched by the full-screen interface.
tools/*.sema<config-dir>Persistent agent tools. Reconciled at boot and on every config apply.
plugins/*.sema<config-dir>Global plugins, loaded once at boot.
sessions/*.jsonl<config-dir>Saved sessions. 200 kept, oldest pruned.
.sema-coder/plugins/projectProject plugins. Loaded after the global ones, so they can shadow.

<config-dir> is $SEMA_CODER_CONFIG_DIR when set, otherwise the OS config directory plus sema/sema-coder: ~/Library/Application Support/sema/sema-coder on macOS, $XDG_CONFIG_HOME or ~/.config below it on Linux. /config prints the path and /config edit opens it.

Every top-level key

keydefaultmeaning and validation
:model"claude-opus-5"String. An empty string auto-detects from whichever API key is set.
:effort""String: none, minimal, low, medium, high, xhigh. Empty means the provider default.
:max-turns50Positive integer. Tool-use rounds allowed in one user turn.
:tool-preview-lines5Positive integer. Result lines shown under each settled tool call.
:modelsAnthropic + OpenAIList of (provider …) groups holding (model …) records. Drives completion, API-key hints and provider routing.
:mcp-servers'()List of (mcp-server …) records. Transport must resolve to stdio or http.
:commands'()List of (command …) records. Exactly one of :run, :shell, :do.
:hooks'()List of (hook …) records. The event must be one of the seven below.
:keys{}Map of action keyword to a non-empty key string.

An unknown top-level key produces a warning and is ignored, never a failure.

Constructors

init.sema — the full surface
(configure!
  (coder-config
    {:model     "claude-opus-5"     ; "" = detect from the API keys
     :effort    ""                  ; none|minimal|low|medium|high|xhigh
     :max-turns 50
     :tool-preview-lines 5

     ; Models offered by /model. Any id typed by hand still works.
     :models
     (list
       (provider "Anthropic"
         (list
           (model "claude-opus-5"    "Claude Opus 5")
           (model "claude-haiku-4-5" "Claude Haiku 4.5" {:effort "low"})))
       (provider "OpenAI"
         (list (model "gpt-5.6-sol" "GPT-5.6 Sol"))))

     ; MCP servers. stdio takes :command/:args, http takes :url.
     :mcp-servers
     (list
       (mcp-server "sema"
         {:command "sema"
          :args ["mcp" "--include" "eval,docs,docs_search"]
          :env {} :cwd "."
          :autostart #t
          :connect-timeout-ms 15000})
       (mcp-server "asana" {:url "https://mcp.asana.com/mcp"}))

     ; Slash commands. Exactly one of :run, :shell, :do.
     :commands
     (list
       (command "test" {:desc "run tests" :run ["make" "test"] :key "ctrl-t"})
       (command "log"  {:desc "git log"   :run ["git" "log" "--oneline" :args]})
       (command "diff" {:desc "wc diff"   :shell "git diff $ARGS"})
       (command "hi"   {:desc "greet" :keep-input #t
                       :do (lambda (state args)
                             (emit :info "hi!")
                             state)}))

     ; Lifecycle observers. The return value is ignored.
     :hooks
     (list
       (hook :turn-interrupted
         (lambda (ctx) (file/write "last-interrupted.txt" (:turn-id ctx)))))

     ; Rebind any action.
     :keys {:mcp "ctrl-p" :resume "ctrl-j"}}))

Command forms

:runAn argv list, never passed to a shell. :args marks where the user's arguments splice in; it is dropped when empty and appended when absent.
:shellA template string run through the shell. $ARGS is replaced with the user's arguments.
:doA (lambda (state args) …) returning the next state, or 'quit to exit.
:descThe line shown by /help and the palette.
:keyA key binding for this command. Weaker than the :keys map.
:keep-inputLeaves the prompt text intact when the command runs from the palette.

Hook events

:session-start{:cwd}
:pre-turn{:input :messages}
:pre-tool-call{:tool :args}
:post-turn{:input :result}
:on-error{:input :error}
:turn-queued{:entry}
:turn-interrupted{:input :messages :turn-id}

A handler that throws is caught and ignored, so a hook cannot break a turn or the interface.

Four layers merge, weakest first: these defaults, a command's own :key, the config :keys map, then runtime bind-key! calls. A key bound to two actions is reported at boot and the first match wins. Tab, Enter, Shift-Enter, the arrow keys and Page Up/Down are fixed.

Precedence and reload

  • Model: the --model flag or the current /model override, then :model, then detection from the API keys.
  • Effort: the current /effort override, then the selected model record's :effort, then the top-level :effort, then the provider default.
  • Loading is pure. A file that does not parse reconciles nothing and leaves the last good commands, servers, hooks and tools running.
  • One apply path is shared by boot, /reload and the file watch. It reconciles commands, MCP servers, hooks and the tools/ directory, then autostarts servers.
  • The full-screen interface watches the config directory and applies a valid save. The plain REPL does not watch; use /reload.
  • The first-run template is generated from the provider table, so the model list in your config cannot drift from the code.

Extending it, step by step

A plugin is one .sema file. Global plugins live in <config-dir>/plugins/ and load first; project plugins live in .sema-coder/plugins/ and load after, so they can shadow. A plugin is loaded once at boot, after init.sema is applied. A plugin that throws prints an error; the agent still starts.

The example below builds one plugin that gives the agent a way to run the project's linter, and gives you a command and a key for it. Each step adds to the same file.

Give the agent a tool

deftool declares the name, the description the model reads, and the parameters. register-tool! puts it in the agent's tool set. The handler returns the string the agent sees.

<config-dir>/plugins/lint.sema
(deftool lint "Run the project linter and return its output."
  {:path {:type :string :description "file or directory to lint"}}
  (lambda (path)
    (let ((r (run-in-workspace f"npx eslint ${path}")))
      (if (= (:exit-code r) 0)
        "clean"
        (:stdout r)))))

(register-tool! lint)

Add a slash command

The handler takes the state map and the text after the command, and returns the next state. Write output with emit, never with display, so the same command works in the full-screen interface and in the plain REPL.

same file, appended
(register-command! "lint" "lint the file under discussion"
  (lambda (state args)
    (let ((r (run-in-workspace f"npx eslint ${(if (= args "") "." args)}")))
      (emit (if (= (:exit-code r) 0) :ok :error)
            (if (= (:exit-code r) 0) "clean" (:stdout r)))
      state)))

Complete its arguments

Completions feed the palette once the input reads /lint <partial>. Return a list of maps; the palette shows :value first and :label as the description.

same file, appended
(register-completions! "lint"
  (lambda (state)
    (map (lambda (f) {:value f :label "changed file"})
         (string/split
           (string/trim (:stdout (run-in-workspace "git diff --name-only")))
           "\n"))))

Bind a key

A key can be bound to a built-in action or to a command name. Runtime binds are the strongest layer and survive a config reload.

same file, appended
(bind-key! "ctrl-g" "lint")

React to the turn lifecycle

Hooks observe; their return value is ignored and an exception is swallowed. From a hook use add-block! rather than emit, because a hook runs outside command dispatch.

same file, appended
(add-hook! :post-turn
  (lambda (ctx)
    (let ((r (run-in-workspace "npx eslint .")))
      (when (not (= (:exit-code r) 0))
        (add-block! {:kind :warn :text "lint is failing"})))))

The rest of the API

Toolsdeftool, register-tool!. A file in tools/ is the persistent form: it is reconciled on every config apply, so deleting the file drops the tool and editing it replaces the tool instead of duplicating it.
Commandsregister-command!, register-completions!. State carries :messages :model :effort :cwd :agent :config.
Keysbind-key!, unbind-key!.
Overlaysregister-overlay!, open-overlay!, push-overlay!, close-overlay!, overlay-merge!, overlay-layout. list-modal and modal-cell build the same widget the MCP manager uses. Key tests: key-name=, key-char=, key-ctrl=. Full-screen interface only.
Promptprompt-text, prompt-cursor, prompt-insert!, prompt-set!, prompt-clear!. Full-screen interface only. To act on what the user is typing, bind a key rather than using the palette.
Outputemit with :info :ok :error :line :raw from a command handler; add-block! from a hook or an overlay.
Helpersworkspace-root, run-in-workspace, resolve-path, config-dir, config-path, tools-dir, *tui-active*, *config*.

Interrupting a turn keeps the history valid

Cancelling during a tool call is how an agent ends up with a conversation the provider rejects: a tool call with no result. Sema Coder repairs the history before the next turn starts.

  • The turn runs as an async task and a second task keeps drawing, so keys stay live and ⌃C lands at once.
  • Every orphaned tool call gets a synthesized, correlated result, and the assistant text written so far is kept.
  • A typed control message records that you interrupted and that partial side effects are possible.
  • Tab queues a follow-up instead of interrupting. /queue lists, edits, drops and resumes.
  • The full-screen interface appends each turn to a JSONL session: one meta line, then one message per line in the shape the runtime takes. It is written to a temp file and renamed, so a crash mid-write cannot truncate the old file. /resume restores a session verbatim. One-shot and the plain REPL do not persist.
